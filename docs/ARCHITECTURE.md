# Architecture

## Runtime boundaries

`AddTaskForm` validates inputs and calls `TaskData.SaveTask`. After a successful write, `TaskViews` rebuilds category sheets and the daily/upcoming lists. `TaskCharts` owns duration-chart series. `AddSleepForm` calls `SleepService`. The workbook-open event calls `RefreshDashboard` so date-dependent lists refresh on reopening with macros available.

`Module1`–`Module5` preserve the original public macro names as compatibility adapters. The existing sheet control that opens `AddSleepForm` is retained. `Sheet1.ToDoList` and `AddTaskForm.ToDoList` delegate to one implementation. The old `GraphsSheet` macro now navigates to the dashboard because the original workbook has no `Graphs` sheet.

## Worksheet contracts

| Sheet | Columns / cells | Contract |
| --- | --- | --- |
| `Master List` | A:F = Category, Course, Task, Start date, Estimated hours, Due date | Authoritative task records; header in row 1 |
| `School Work` | A:F, same schema | Derived school tasks; course and due date required |
| Other category sheets | A:D = Category, Task, Start date, Estimated hours | Derived non-school tasks; no retained course or deadline fields |
| `To-do and Sleep` | A3:B… | Task and start date for tasks starting today |
| `To-do and Sleep` | C3:D… | Task and start date for tomorrow through Date + 7, sorted ascending |
| `To-do and Sleep` | F8:F14 | Sunday through Saturday sleep hours; blank means unrecorded |
| `To-do and Sleep` | H19 | Descriptive mean of recorded weekdays |

Valid categories are School Work, Health, Social, Daily, Work-Finance and Extracurriculars. Estimated task hours must be positive. School due dates must be on or after the start date. Sleep hours may be zero and may not exceed 24.

## One task store, several views

The master is written once. Category views are rebuilt from it, rather than independently maintaining duplicate records through form code. Categories sort by descending start date. Their charts reverse the category axis to display earlier dates first, with one estimated-hours point per task.

Category clear macros remove matching records from the master and regenerate views. Clearing the master removes tasks from all derived lists while retaining the sleep log. Clearing just daily/upcoming output is temporary; the next refresh derives those rows again.

If saving a task succeeds but a later refresh fails, the form explicitly reports that the task was saved and closes to discourage duplicate resubmission. The user can fix the source issue and run `RefreshDashboard`. Validation failures occur before writing and leave the form open.

## Deterministic refresh

1. Validate nonempty master rows before replacing any views.
2. Clear only owned data columns below each header.
3. Rebuild category rows and sort bounded data ranges.
4. Update one `TaskDuration` chart per populated category; remove that chart when the category becomes empty.
5. Clear and rebuild daily/upcoming lists, using calendar start dates and explicit boundaries.

The views are regenerated by macros, not live formula tables. Manual edits to master cells require a refresh. All data writes target `ThisWorkbook`; having another workbook active does not redirect them.

## Sleep summary

```text
average sleep = sum(recorded weekday hours) / count(recorded weekdays)
```

A recorded zero contributes to the denominator; a blank does not. The seven slots are a weekly template with no dated history. The revised message describes the entries without classifying a user's health. The original list binding in the sleep form is removed before filling weekday options, avoiding an initialization error on a bound ComboBox.

## Migration from the original prototype

| Original concern | Implementation |
| --- | --- |
| Task copied by separate form routines | Master record plus generated category views |
| Refresh and form closure after invalid input | Guard clauses before any write or refresh |
| Hidden stale due-date/course fields | Ignored for non-school tasks |
| Six repetitive full-column chart/sort routines | Parameterized category services and bounded ranges |
| Daily list left old rows behind | Clear-before-rebuild behavior |
| Upcoming region had no generation routine | Explicit next-seven-days view |
| Unqualified sleep ranges | Explicit dashboard worksheet |
| Invalid 24-hour check and fixed seven-day denominator | Numeric bounds and recorded-day average |
| Two loose files contained identical form code | Preserved under `src/legacy/` with provenance note |

The workbook retains its original Group 21 identity and UserForm designers. External resource links remain historical project content; their destinations were not validated. No completion tracking, recurrence or calendar synchronization is implemented.
